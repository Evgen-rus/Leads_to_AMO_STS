# Leads to amoCRM — STS

Рабочий поток: Google Sheets → локальная SQLite → amoCRM → ссылка на сделку обратно в Google Sheets.

## Гарантии

- Строка сначала сохраняется в SQLite, только затем отправляется в amoCRM.
- ID и URL созданной сделки сначала фиксируются в SQLite, затем URL записывается в Google Sheets.
- Любое непустое значение в колонке результата блокирует отправку строки.
- Если запись URL в Google временно не удалась, следующий запуск повторит только эту запись, не создание сделки.
- Если заголовок колонки результата не найден, ссылка записывается в колонку `K`, а `K1` не изменяется.
- Перед созданием выполняется поиск сделки по полю `Комментарий` и исходному ID.
- `--dry-run` не создаёт колонку, не пишет в Google, SQLite или amoCRM.

## Настройка

Заполните `.env` по образцу `.env.example`. ID воронки `11105258`, этапа `87201098` и поля «Комментарий» `1461977` зафиксированы в коде по ТЗ STS.

Текущие временные названия входных колонок: `ID`, `Номера`, `Канал`, `Источник`. Их можно переопределить через `.env`, когда будет известна точная структура листа.

## Безопасная проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe run.py --dry-run --limit 10
```

Dry-run читает реальную таблицу, но ничего не записывает. Запуск без `--dry-run` создаёт сделки, поэтому выполняется только после отдельного подтверждения.

Отдельный утренний перенос из вкладки менеджеров во вкладку AI:

```powershell
.\.venv\Scripts\python.exe transfer_to_ai.py --dry-run
```

Реальный перенос выполняется обычным запуском без параметров:

```powershell
.\.venv\Scripts\python.exe transfer_to_ai.py
```

Этот скрипт только переносит строки между вкладками и не обращается к SQLite или amoCRM.

## Локальный просмотр amoCRM

Запуск: двойной щелчок по `launch_amo_browser.cmd`. Откроется браузер; окно сервера оставьте открытым. Закрытие окна останавливает сервер.

Или из папки проекта:

```powershell
.\.venv\Scripts\python.exe amo_browser.py --open-browser
```

Адрес по умолчанию: `http://127.0.0.1:8765`. При занятом порте: `--port 8766`.

В интерфейсе доступны воронки и этапы, фильтр по дате **создания** сделки (включая обе границы, время Новосибирска), поиск, просмотр истории, комментариев и транскрибации, прослушивание аудио. Можно открыть сделку по её ID или ссылке amoCRM.

Для выгрузки выберите до **10 сделок**, отметьте нужные материалы и скачайте ZIP. Материалы также остаются локально в `data/amo_exports/`: отдельная папка выгрузки, внутри — воронка, затем сделка. Названия включают ID, поэтому одинаковые названия не смешиваются. Отсутствующие материалы и ошибки отмечаются в результате выгрузки.

Существующие настройки берутся из `.env`; токен остаётся на сервере. Сервер слушает только локальный адрес. Обращения к amoCRM выполняются только на чтение. Скрипты отправки в CRM, Google Sheets и их база не изменяются. Сопоставление статусов в этот инструмент не входит.

Диагностика: журнал `logs/amo_browser.log` автоматически ротируется. Он содержит операции, коды ответов, длительность запросов, повторы и результаты выгрузки; токены и тексты разговоров не записываются. Чтение amoCRM использует существующий лимит 5 запросов/сек и до 4 попыток для временных ошибок, с учётом `Retry-After` при 429.
